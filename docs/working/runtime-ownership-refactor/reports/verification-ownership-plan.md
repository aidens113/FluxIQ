## Serial shared authorities and concrete ports

The lead freezes these before parallel source release; worker units do not edit shared/root/package barrels or common service composition.

Reuse actual executable graph/trace/draft, `@fluxiq/contracts/records`, canonical runtime failure, `runtime/reference-time`, `runtime/action-permissions`, model/provider and agent-ledger authorities. New verification contracts must not re-declare those existing owners. The full call-intervention receipt still lives in `model/flow-adaptation.ts`; if the collector moves, promote that exact neutral receipt once or make the collector generic over original receipts, without making a second abbreviated intervention.

1. **Rich data authority.** Move exact existing result DTOs once; old names alias/reexport them. `contracts/run-result-summary.ts` currently imports `AutomationStudioTrialSiteChange`/`AutomationStudioTrialChangeFinding` from Studio `flow-bootstrap/trial-change/contracts.ts`. Canonicalize the exact neutral packet/proof DTO closure, keeping host readings opaque; do not make a second site-change summary. `repair.ts` and verdict/citation readers import diagnosis/defect/checked data from `llm/harness/structured-response.ts`: promote those exact authorities once, retaining all diagnosis fields and the transport-owned truncated marker. `standing-no` is rich Core-only data, not an opaque capability.
2. **Keep private provenance private.** The separate `unconfirmed-inspection/hint.ts` is the real private owner: AsyncLocalStorage scope plus WeakMap binds the original hint, summary snapshot, round and graph/replay signatures. Its future move must retain one registry/owner and reject copied, stale or cross-round hints. No serialized carrier grants inspection, completion, permission or acceptance. The initial three cuts leave this source untouched.
3. **Accounting source port.** Reuse `ModelRunBudgetLedger` from `runtime/agents/ledger`. A narrow source exposes the original `current.ledger` methods `snapshot`/`callRecords`, optional original historical gate and diagnostic. It is a view of the real purse, not a new purse/session DTO or ledger. Call methods on the original ledger receiver; retain canonical historical fields over later overwritten metadata, unknown-history refusal and omitted-call count. Never synthesize zero spend or call `open` merely to project a receipt.
4. **Read-progress policy.** Required host adapter methods read the existing full read-account: `stopMeaning(read): list_ended | page_bound | other`, `observedEnd(read): boolean`, and whether continuation names a next part versus a growing/unknown list. Core numerical facts consume these meanings; they do not interpret `control_disabled`, `control_absent`, `scrolled_to_end`, `page_limit`, `next_page`, `load_more` or `infinite_scroll`. Missing/unreadable evidence remains unknown, not an observed end. Preserve the existing distinction: inferred stop meaning alone is not `observedEnd`; a one-page absent next control is not proof of completion.
5. **Repair presentation port.** A cohesive immutable port renders the existing coded finding/fix and flagged-row/kept-number lines and supplies the existing screened-judgement result `{ judgement?, withheld }`. Canonical code owns classification, ordering, construction and failure bounds; existing Studio wording stays byte-identical until the paired host-presentation move. The host continuation renderer returns the exact `{said, fix}` currently produced by `read-account/list-continues.ts`; Core must not hardcode page/reply/scroll/retry-control instructions.
6. **Later model/evidence/result ports.** `ModelProvider<Request>` already exists; `AutomationStudioLlmProvider` merely specializes it with Studio's task request. Do not redeclare a provider. A future verifier call port accepts the original verification scope/evidence/check/ask/recheck/signal plus the actual ledger; returns the exact validated diagnosis/usage/intervention/diagnostics. Studio's original harness keeps prompts, authorization and activity/storage. Evidence readers fetch actual datasets/schema/rows/instructions/called graph revisions; a result sink stores actual outcomes/receipts and graph judgements. Repair/rerun callbacks remain separate from evidence or verdict readers.

Passive selector/card/credential detection used only to redact evidence is privacy handling, as `residual-runtime.md` states; it is not target resolution. Reuse canonical privacy readers (or one narrow privacy port) instead of moving a generic screen downstream solely because its text mentions selectors. Active parameter grammar, DOM/resource identity, URL/page state and control/action interpretation must use the downstream trusted owner.
