Proposed narrow `service/execution-admission/binding` owner: retain the original service/project-pool/Flow objects privately, verify the SQL Flow row is present and not deleted, open/reuse one durable continuation anchor, and issue a frozen empty proof tracked in a private WeakMap. Only its original `readBinding(proof)` produces A1's binding/baseline/digest. Default owner/continuation keys come from that persisted Flow; coverage epoch comes from the durable anchor, not a build UUID, candidate revision or lease epoch.

Actual resource APIs expose an original `hostRuntime.hostResources` port, a scheduler/lease scope cached by that original port, and an optional current lease `{resourceKey, epoch, sessionId?, holder}`. Retain the original port/lease and verify currentness through its actual scheduler/scope; do not accept a copied lease DTO as original ownership. Root composition keeps the same host object/receivers. A lease epoch/session identifies current lease fencing, not resource freshness or proof that old work settled.

Those APIs expose no durable resource namespace/reopen mapping and no authenticated freshness/completeness witness. The production default proof therefore stays **unverified**, with a conservative project-local unknown-resource fence shared by that project's Flows. A verified original leased key may be retained as an additional association; never invent native/gateway resource identity or discard the unknown association because a lease changed. Complete baseline requires an explicit trusted actual resource-lifecycle owner proving original identity, quiescence/freshness and prior mapping; none was found in these APIs. Empty telemetry/journal, current page, reset result, new session or a new SQL coverage table proves none of those facts. An isolated fresh test resource can have its own authentic test owner, separate from production.
