## Applied bounded change and releases

- `service/recordings/store.ts`: scoped load returns the actual local recording, loads only its addressed durable namespace when the owned cache is unavailable, validates stored ID/explicit ownership, and returns null for an absent project recording. `getRawRecordingSession` returns that local value directly. Completion recovery uses the same actual project; a scoped read cannot evict a foreign or ambiguous global mirror.
- New `mirror.ts` is the sole runtime recording/normalized mirror writer. It serializes publication, owned reads and compare/delete by the original repository object and exact opaque ID. All actual runtime writer sites route through it; the remaining direct puts are ready-only seed fixture initialization. Memory create checks and publication are atomic, so concurrent cross-project same-ID memory creation explicitly refuses one caller. Durable same-ID projects remain supported.
- The mirror retains only the last publication's actual project (or unscoped origin), never another document/read cache. Scoped ownership checks compare requested project, current body metadata and this retained origin under the same queue. It preserves valid original cached prepared/legacy inline bodies and omitted-time retry identity. This is data-cache provenance, with no execution/admission rights. Trusted direct-legacy repository fixtures retain matching-project behavior absent contradictory managed provenance; arbitrary hostile private-repository mutation is outside this trust boundary.
- New `normalizations.ts` uses actual project index/file ownership for durable reads, validates both normalized timeline ID and the index's recording ID, and never borrows a foreign/ownerless global slot. Actual addressed legacy files may supply missing ownership metadata. Supplied normalization project metadata is stamped even without object storage. Scoped deletion preserves foreign/ambiguous normalized mirrors.
- Existing `deletion.ts` now owns single and bulk recording cleanup. It validates every scoped address before mutation, conditionally deletes mirrors under the sole writer queue, and preserves foreign same-ID data. Bulk operations acquire the existing per-project mutation locks in deterministic ID order; single cleanup keeps the original private pipeline callback/receiver without double acquisition. Physical paths, project indexes and object cleanup remain scoped.
- The lead serially released only the documented `service.ts` recording seams: create; final append/finalize mirror puts; scoped list/single/bulk deletion; normalization metadata/mirror publication and project normalized reads; project normalized loading; the two private pipeline first reads; and all-project summary scoped lookup/composite address. The exact create and append/finalize releases are recorded in the brief and lead messages. Extracting cleanup into its existing collaborator keeps service below its unchanged baseline budget. Summary DTOs retain real project IDs.
- Canonical capture/sink/recording/IO/admission owners, root/package exports and the required `proposal-candidates.test.ts` fixture are untouched by this unit. The lead's separate final native registration additions to service.ts are frozen for the final read-only checks.
