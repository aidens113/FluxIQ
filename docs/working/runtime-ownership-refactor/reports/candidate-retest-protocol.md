## Two authorities, kept outside model data

**Generic gate permit.** Add a small neutral authority under `runtime/agents/gates/reentry/`. Its factory owns an opaque loop scope and private WeakMap/ledger; it exposes separate issuer and consumer handles. A permit is a frozen issued object whose membership is checked by the consumer, not a structural type, string, symbol field or JSON token. The generic module knows only an opaque gate owner, canonical request key, generation, completed ordinal and remaining count; it imports no Studio, Flow, host or browser code.

Studio's candidate owner binds that generic permit to `(loop scope, gate instance, candidateId, revision, digest, baseDependencyDigest, environment identity, completed-trial ordinal)`. The request key is built after the existing complete receipt/input validation, including default-to-latest normalization; neither model call IDs nor tool names are authority. A receipt for the old candidate cannot become a permit for the new one. The generic ledger allows at most one permit per completed ordinal and refuses duplicate issuance even if the issuer is called again.

**Live execution admission.** Add a separate build-scoped execution-safety authority, driven by actual dispatch/engine/command facts. It must be shared by exploration, nested/partial execution and whole trials in this build, and survive candidate revisions/run IDs. It records a potentially committing send before dispatch, and seals its terminal outcome from actual acknowledgements/engine effect checks. Missing/failed collection, malformed completion, an unresolved committing send, or a child/required-mode uncertainty remains pending. A verdict, empty `acts`, page digest, reset return value, fresh revision, or model claim cannot clear it.

The trial factory associates a private execution authority with the concrete port; the gate obtains a live admission lease from that authority before any start hook or live trial. Use a Core-owned companion handle/registry, not a new JSON field in `AutomationStudioCandidateTrialResult`. A wrapped project whole-trial port must explicitly forward that same authority. A caller-supplied legacy port with no observed-execution authority gets no new automatic live-reentry capability; absence is an explicit safety-unverified refusal, not an invented clear receipt. Existing pure fake-port fixtures can be composed with a test-controlled observed no-dispatch scope while preserving their original success assertions.

Minimum additional private facts:

| Fact | Trusted producer and use |
| --- | --- |
| Execution identity and completion ordinal | Gate/actual trial factory; binds the permit and prevents reminting after a refusal. |
| Dispatch coverage and terminal settlement | Engine/command execution owner; includes all nested attempts and sends, not only landed acts. A scope that did not observe all dispatch cannot attest clear. |
| Pending/terminal uncertainty and safety generation | Shared execution authority; checked again at gate entry. New uncertain exploration after issuance invalidates an older clear lease. |
| Next execution kind | Trial factory's private cache/environment owner: live, cached rejudgment, or offline. A cached rejudgment must be pinned to the same retained run/evidence; it cannot silently fall back to live execution using a no-dispatch admission. |

Known landed acts do not become a new blanket refusal: the existing before-state/delta/targeted-undo policy still handles them. Unknown required-command outcomes remain terminal under their existing command-ledger rules, even if the page later appears unchanged or the hook says reset. A non-required uncertainty can clear only through the execution owner's existing authenticated settlement path; this unit must not invent a new automatic resolution policy.

## Entry and lifetime algorithm

1. Keep offering, schema/receipt validation, cancellation, tool-call allowance, deadline/cost gates and strict ordinary retry controls first. Expose a trusted **input-only** `gateReentry` collaborator in the loop configuration; it never enters prompts, persistence, tool schemas, execution-result JSON or evidence accounting.
2. After a completed, validated transient trial outcome, the candidate owner may issue one permit while the latest candidate still matches, trials remain, no same-failure/closed/final condition stands, and its private execution authority can establish admission. No permit after `yes`, `no`, missing/invalid outcome, unresolved commit, abort, or exhausted allowance. Do not derive issuance from `retestsLeft` or `retry_allowed` in JSON.
3. When a repeat/cache would otherwise block, the loop asks the private collaborator for a permit for that exact normalized request. Its own consumer validates and consumes it synchronously, before any `await` or gate call. It lifts only that candidate gate's stale repeat/memo answer for this call. It does not delete general repeat history, reset mutation epochs, manufacture progress, or alter the parsed execution result.
4. Call the existing gate through normal `runCall`, preserving history, accounting and activity. The gate atomically excludes another in-flight entry, revalidates latest identity/trial allowance/signal, and obtains a current execution-admission lease **before `prepareStart`**. Recheck the lease/generation at the live execution boundary so uncertainty appearing during a hook or admission read cannot race the dispatch. A first test of a fresh revision must also honor the shared pending-uncertainty barrier.
5. Then retain the existing order: offline-first handling; optional admission/witness notes; live start preparation; defaulted/narrowed `cannotUndo`; actual `beforeTrial`; trial-count accounting; actual port; trial-acts/standing/failure-memory updates; post-trial view. Live admission never replaces those checks. Cached rejudgment/offline execution must keep their existing no-Flow/no-start-hook behavior and cannot promote an offline yes.
6. Any actual gate entry invalidates outstanding permits for its old ordinal, including an entry reached normally because the page changed. A refusal, reset failure, insufficient purse, unchanged page, recovered stall, failed observation, or rejected permit does **not** mint a replacement. The consumed permit remains spent. Fresh state/proven precondition progress can still use existing admission rules; only a new completed counted trial can mint the next ordinal's credit. Existing trial refunds for genuine not-started unaffordable calls stay intact and do not mint credit.
7. Route candidate stall recovery through this same entry helper rather than the current direct `runCall` shortcut. Preserve once-per-ordinal stall recovery and all tool/duration/cost limits. Ordinary calls, private batch/prior-call members and amendments cannot borrow this permit; their current fail-closed controls remain. Dispose/revoke the **permit** authority at loop end/abort. This never settles or erases execution-owner uncertainty: a continued build/new authoring loop must reuse or rehydrate its existing pending state, not create an empty safety scope. Broader restart persistence stays with the existing command/session owner and cannot be treated as proved by this in-process permit design.

The permit reaches an admission door. It never authorizes a gesture. The execution authority independently prevents an unresolved earlier gesture from being sent again, including after re-submission or a newly allocated run ID.
