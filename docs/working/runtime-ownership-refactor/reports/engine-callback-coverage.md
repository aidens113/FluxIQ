# Actual engine callback coverage (read-only review)

Outcome: Done (source inspection only). Only this report changed. Recording and all implementation sources remain frozen. Paths below are relative to `packages/fluxiq/src/`.

The current presence scan is conservative compensation for real call-site gaps; deleting it globally would be unsafe. `execution-admission/internal/driver.ts:56-57` prepares an actual engine entry, then marks that entry unverified if **any available** listed callback lacks a recognized identity. It does this before knowing whether that callback will run. `ExecutionObservationSource.frameCompletion` refuses a gap, so an unused available method can prevent coverage even when every actual descendant settled. This is different from an actual unsupported callback invocation.

Conversely, several actual calls bypass observation, and several scanned host names have no engine invocation. Some fully instrumented helpers use generic `invokeObservedExecutionCallback[Sync]`, not `invokeAutomationCallback[Sync]`: they retain the original method/receiver/tuple, but do **not** run the engine's `ensurePure`. A registry exemption during presence checking is not itself a managed contract for a later generic invocation or a different receiver.

## Safest first corrective cut

1. Make only the actual host expectation/fact read paths consistent: `transitions/comparison.ts` effect-check call, `recovery/run.ts` readiness call, and `step-loop/{entry,success-check}.ts`. Invoke the original evaluator with original host receiver and unchanged four arguments through A; pass the existing private observation companion to the two fact helpers. Retain current returns, catches, ordering and signal behavior. Do not register the forwarding `hostExpectationEvaluator` closure as a substitute for its original host function.
2. Beside those subjects, prove original receiver/tuple/result/error identity, first unsupported return retained with no completion credit, unsupported throw/late completion staying fenced, and absent/never-invoked host callbacks producing no fabricated call receipt. This is proposed acceptance, **not executed evidence**. Keep the broad presence protection until each still-direct row has a truthful observed route; do not globally remove it with this four-file cut.
3. For real host read contracts, reuse `AutomationExecutionAdmissionSource.manage(ManagedExecutionCallbackRegistration)` with original `{receiver: host, callback: originalMethod}`. The host reference survives option copies; registering a transient options object does not. Safest configuration insertion is immediately after `createAutomationExecutionAdmissionSource` in `programs/.../runtime/build-execution/create.ts:22`, before connect/return and before any reservation, from a narrow framework-only list supplied by the actual host owner. The current `createAutomationGraphOptions` accepts only host data and has no such contract port; it must not infer one. Use the existing registration type authority, not a copied DTO or whole-Service Pick.
4. A real side-effect-free original body may explicitly receive `no_direct_effects` only from its trusted owner after inspection. Otherwise require the original producer's private `managed_direct_effects` completion consumer; unsupported bodies remain unverified. No function-property/name/status/page-evidence purity, no "read returned" completion invention, and no observer handles in host/native/model arguments. Keep actual engine/native/output descendants in the frontier; never replace their completion with the outer callback's return or an empty child list. Do not expand C's reset/classifier work or B's native receipt unit.
