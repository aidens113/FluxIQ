## Freeze this first interface

Choose a deliberately bounded first unit: move the worked-example tails of the four format sections, preserving every existing web example byte and its position. Do not combine this with the mixed prose, facts, intent, word-list or fingerprint migrations.

```ts
type AutomationStudioFlowScriptExamples = {
  version: string;
  format?: readonly string[];
  act?: readonly string[];
  loop?: readonly string[];
  state?: readonly string[];
};
// Optional member of AutomationStudioLlmEvidenceRuntimeBinding:
flowScriptExamples?: AutomationStudioFlowScriptExamples;
```

Arrays are exact authored lines, including the existing Example headings and indentation. Core owns the grammar and section order; a client contributes only each section's worked-example tail, never a replacement grammar. A pure Core renderer accepts the explicit examples and joins each grammar prefix with its matching tail using one newline; do not parse Core source strings at runtime or use regex node-id replacement.
At binding, validate a fresh copy: existing version syntax; only the four named arrays; string lines without control characters except line feed; finite total text bound (64 KiB) and array/item bounds sufficient for the moved fixture. Reject malformed supplied vocabulary at bind, not midway through a build. Omitted vocabulary/sections mean no examples. Never infer web examples from domainId, node ids, capabilities, systemInstructions text or a legacy constant.
Keep `systemInstructions` and registry `nodeDescriptions` unchanged. Export the new type/renderer through ordinary owning barrels and the existing public automation-studio surface; no Core import of Down. Down's runtime type should require its own examples because the web producer always knows them, while Core's binding member remains optional for old clients.
The current old-client behavior is web examples unconditionally embedded in Core, even without systemInstructions. The new compatibility default is intentionally example-free grammar; it preserves callable signatures and parser/executor semantics but changes those old clients' model prompt text. Their missing examples must never trigger a web fallback. During this first unit, existing inline medium/node prose remains explicitly tracked P10 debt, not a claim that the whole prompt is medium-neutral.

1. **Core contract, no prompt change yet.** Own new `R/flow-bootstrap/plan/script-examples/{contracts,validate,render,index}.ts`, `script-examples/tests/*.test.ts`, `R/llm/harness-options/binding.ts`, `R/llm/domain-instructions/binding-check.ts`, and required public barrels. Bind-time validation runs independently of whether systemInstructions exists; its present early return must not skip example validation. Tests prove absent/partial sections empty, exact line preservation, independent instances, malformed text rejected and no Core-provided example fallback. Freeze the interface before unit 2.
2. **Down supply, still no consumer change.** Own new `domain/src/runtime/llm-evidence/script-examples/{format,act,loop,state,examples,index}.ts` and colocated tests, plus `domain/src/runtime/llm-evidence/tools.ts` and its barrel. Move copies of the four existing worked-example tails, attach required `flowScriptExamples`, and pin old rendered strings/digests before Core extraction. Source strings are authored examples, not run artifacts. Existing Core ignores the new companion until unit 3, so this step does not change web prompts.
3. **Core extraction and all consumers together.** Own `R/flow-bootstrap/plan/flow-script-format.ts`, its format/loop tests, `evidence-schema.ts`, candidate `authoring-loop.ts`/tests, subflow `builder-loop.ts`/tests, and `R/llm/harness-options/bootstrap-completion.ts:273` only for the binding Pick. Remove worked-example tails from Core constants; render them only from explicit binding. Extend the completion factory as `(size = defaults, examples?)` so one/no-argument callers remain valid; its exported constant uses no examples. Widen both narrowing Picks to carry examples; candidate and subflow render from `input.submission.binding?.flowScriptExamples`, using the existing binding path rather than service-wide plumbing. Recheck Down parity after this switch; migrate Core tests that expect web example fixtures to Down and keep Core grammar/parser tests generic.

The units are serial because step 2 freezes the before/after fixture and step 3 changes the meaning of existing constants. Do not merge step 3 without the already-bound Down producer. No package version/git work belongs to the implementing worker; lead owns paired release/integration decisions.
