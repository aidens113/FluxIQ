# D: authoritative frozen-call provenance and admission

Read-only follow-up; Core paths below start at `packages/fluxiq/src/programs/automation-studio/`; `R` means `runtime/`. Down paths start at the paired WebExtension checkout. No C implementation or A/B source was read.

## Actual producer chain and remaining gap

- Core `R/llm/harness-options/registry.ts:246-256` frames the host call and dispatches the selected option; `binding.ts:689-706` forwards explicit request fields into the domain binding, including permission/referenceNow. JSON `value` is model input; it is not execution provenance.
- Down `domain/src/runtime/llm-evidence/tools.ts:497-544` chooses a connected session, restores build memories and routes `core.run_node` to `runWebOutputNode`. This path directly dispatches a web action; it does **not** execute a native Core graph node whose input trace Core could already freeze.
- Down `node-run/catalog.ts:84-103,125-134` resolves a runnable canonical node from registered definitions, even correcting a near name. Therefore raw `value.node` is not sufficient canonical identity/version evidence.
- Down `node-run/run.ts:268-304` shapes handles, restores held literals, resolves current target/extraction stores, then labels the resolved identity. `plan-resolution/resolve-plan-node.ts:740-755` turns a handle into selector/frame/element using `targets.resolveOn/resolve`; this is the authoritative resolution point, before later lowering.
- Down `run.ts:344-353` asks Core's permission callback with the trusted web action floor; `366-374` checks origin and shown-address policy; `387-396` lowers `ran` into actual command parameters and dispatches under retries. Canonical node identity, logical resolved node parameters and lowered command are different artifacts.
- Down `run.ts:550-554` returns `draft.ranWith = nodeCall(value, flowParameters(written,ran))`. `node-call.ts:23-39` deliberately restores the model's extraction handle instead of preserving the resolved extraction request. The returned value is an authored Flow representation, **not** an attestation of exact effective inputs. Element parameters are generally resolved there, but that does not make every `ranWith` authoritative or handle-free.
- More lowering happens after that logical point: `node-run/retries/dispatch.ts:110-111` stamps extraction reference time; `tools.ts:720-725` adds check-wait parameters in the gateway wrapper; `retries/reacquire.ts:40-51` can issue a separate fresh-parameter command. Capture must include the final normal/fresh dispatch and identify which successful receipt it describes, not just the first `ran` object.
- Down's gateway result is client-origin data (`capture.ts:55`); public result metadata and typed `draft` fields cross Core's JSON reader. A structurally valid or frozen JSON object is not a trusted producer attestation. Core `R/llm/evidence-loop-decision.ts:125-129,156-166` screens execution keys, not provenance. `call-record.ts:42-70` deliberately carries the domain draft opaquely.
- Existing target stores reduce accidental remapping (`plan-resolution/target-packets.ts:449-464` resolves current/on-page entries), but that is no guarantee across a new runtime/store/session/generation. A prior raw `tN` or extraction handle must never be looked up again as authority for an identical rerun.

## Existing rerun seams: reuse their components, not their control path

- `R/llm/node-tools/rerun-check.ts:124-131` forwards the ordinary call when no replacement stands, but a done lasting replacement becomes `replay:verify`; it supplies no frozen effective execution itself.
- `R/llm/evidence-loop.ts:415-420` with `rerunReplaces` calls `step-place` first. That can put the page back/replay prefixes, so it violates the batch's no implicit repositioning contract.
- `node-tools/replay.ts:179-195` uses authored `ranWith` and may add assembled record output. Down `node-run/replay.ts:296,328-353` scopes a row, resolves the current stores and changes read options before dispatch; it answers `core.replay.*`, not the original result-code baseline. It cannot serve unchanged as the identical-call batch executor.
- Therefore there is currently no proven end-to-end seam for the required frozen call. Core-only reconstruction from raw `draft.ranWith` is insufficient. Add a small host-local provenance seam and a Down execution mode; ordinary clients without it remain unproven, while the paired web adapter implements it.

## Minimal Core-owned host-local boundary

1. Add a focused `R/llm/node-rerun-provenance/` module. Use a process-local opaque capability/registry plus an async call scope established only around Core's fully wrapped execution. Do not add a model JSON flag, result-schema field, serialized token or provider tool parameter that can mint or select an execution. The only model selector remains the prior loop `callId`.
2. Prefer a scoped capture/execute channel adjacent to the existing `harness-options/evidence-build-scope.ts` precedent. That file documents and solves bundled Core versus dynamically loaded Core copies through one process-global registered-symbol store (lines 43-50,70-95). A fresh module-local ALS/WeakMap would silently fail in that host; share the store across copies and scope records by binding identity + project/Flow/build/loop generation + actual call id. Scope nesting and concurrent calls must be isolated.
3. A trusted adapter sees a **Core-created capture sink**, never parsed from `value`, and submits an immutable host record after authoritative resolution/dispatch. Core privately retains canonical node id/version, resolved concrete node parameters, effective node-port inputs (explicit `{}` when this web path has none), reference instant, scope/definition/authorization generation, result-code baseline, and an adapter-owned opaque execution capsule. No selector, row, credential or capability is published to the model/logs.
4. Keep two linked representations: canonical logical resolved inputs for Core's effect resolver/repeat key, and exact lowered command/effective scope used by the adapter. Attest the relationship at the producer; never infer it from matching field names. Record dispatch attempts and the successful selected attempt, including refreshes/defaults. If the host cannot account for an effective input/default or the semantic subject changed during refresh, leave the call unproven.
5. Core seals a registry entry only after the original fully wrapped call settles as valid success with an actual dispatch receipt and no uncertainty/person-needed/synthetic verify/written/refusal override. A capture alone is provisional. Outer permission/baseline wrappers can replace a successful-looking inner result (`flow-bootstrap/action-permissions.ts:383,444`), so the adapter must not independently mark the call usable.
6. For a selected batch member, Core enters an execute scope containing that registry entry/capsule, then invokes the **same original wrapped `executeTool`** under `core.run_node`. The Down adapter consumes the opaque capsule by object identity/binding registry membership before normal model-handle resolution. Copying capsule-shaped JSON, changing `value.node`, adding a `frozen` field or returning a fabricated `draft` cannot activate this branch.
7. Resolve trusted effect safety anew against the attested canonical node + actual concrete parameters/inputs and current canonical registry, including policy output composition. Freeze a canonical logical key, not the model spelling or call alias. Compare definition/version, binding/session/authority scope and relevant effective inputs before each member. Unknown/malformed/commit/unresolved conditional effect, lasting declarations/observed uncertainty, or state without trusted repeatSafe stops unrun. Never obtain “safe” from the old payload.
8. Parameter equality means semantic inputs remain fixed; retry refresh may change selector/address only by existing trusted same-subject identity/source reacquisition. Never use a fresh handle number or array position to choose a subject. Store original subject/frame/resource/source provenance in the capsule; validate current context without resolving the original model handle. A truly gone or ambiguously matched subject stops. No navigation/reset is performed to make a capsule valid.
9. Re-enter existing permission, origin/address, target/actionability and command/receipt guards; do not cache a permission verdict. Down should share the prepared-command execution/postprocessing implementation with ordinary run (including observation-only nodes), preserving original result-code semantics and full current evidence. It must not call existing replayStep as a shortcut or silently reassemble outputs/rows. Any wrapper that alters effective input must be reflected in the attestation or refuse the frozen execution.
10. Reuse the original domain dispatch retry/effect-check implementation and gateway; do not call Core nativeRuntime.execute directly or create a second gateway path. Include normal and fresh retry dispatch in capture; reuse original fixed reference instant and actual explicit browser/session/frame scope, not a new active target default. Where a scope was implicit, the adapter must bind and validate it from authoritative capture/execution context before attesting; absence is unproven, not guessed.
11. No capsule survives process restart, scope reset or host-binding replacement by restoring raw JSON. Resume can make a fresh ordinary execution prove it again. Dispose registry entries with the loop; keep capture data out of durable project state and public schemas.

## Pre-admission that `runCall` does not provide

- Core `evidence-loop.ts:638-657` parses the decision against the offered schema and binding context; `714-735` rejects withdrawn looks; `740-747` handles offered final tools/deadline/final slot/unknown tool. Each member must be admitted as its original `core.run_node` capability under the **current** offer; being nested in an offered batch is not authority.
- `750-783` computes signatures, checks current eligibility/wrap-up withholding, repeat outcomes and answered-request/answer-check rules; `788` allocates a unique call id; `794` checks maxToolCalls. These live outside `runCall`. Extract one reusable admission routine and invoke it before every member, along with cancellation/deadline/remaining purse guards; do not jump directly to the closure or set `rerunning=true` globally.
- Explicit batch rerun intent may bypass the *successful original's answered-cache* once under list admission, as explicit amendments do; it must not suppress failed/uncertain/withheld/authority guards. Record/check the ordered canonical list once independently of per-member epochs, while retaining individual safety/outcome guards. Ordinary single-call behavior must remain unchanged.
- `runCall` itself registers/counts/records receipts at `404-406,434-466`, but **always** calls `draftRecord` at `469`, mutates replacement/reversal state at `470-471`, and may execute automatic recovery at `517`. Add an explicit internal batch settlement mode: no draft additions/replacements/reversals/acts/places, no implicit recovery tool/reset. Preserve digests, accounting, evidence/privacy, actionability/failure metadata, history, no-progress and terminal outcomes. Return a member outcome rather than interpreting `undefined` as success.
- Members must not each carry the envelope's model usage or consume another provider decision. Actual member calls consume ordinary tool/evidence allowance; rejected unrun members produce refusal/history without claiming an execution. First final failure/changed code/uncertain outcome/authority loss/allowance stop ends the list, retains prior receipts and executes nothing later. The envelope is never an executed node or proof of whole-Flow success.
