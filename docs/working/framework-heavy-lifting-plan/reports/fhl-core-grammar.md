# Report: fhl-core-grammar

Root R = `!FluxIQ/packages/fluxiq/src/programs/automation-studio/runtime/flow-bootstrap`. `C/` = `!FluxIQ/packages/contracts/src/record-sets/process/`. Format file `F` = `R/plan/flow-script-format.ts`. Read-only; excerpts only; nothing run. Extends `fhl-core-surface.md` (not repeated: build tools, judge pipeline, retries). `dsl/` is a generic Flow-definition compiler (`defineFlow`, `compileFlowDefinition`); it carries no authoring duty and is not a lever.

## Outcome

Done. Findings:

1. The model's grammar duties fall in five groups: (i) choosing steps and handles (class a, stays), (ii) writing predicates (`where`, `when`, `done when`, handler facts), (iii) declaring effects (`consequences`, `undoes`, `resetDestination`, task-spec `effect`), (iv) declaring structure (paging, repeat, dedupe, `$input`, parts), (v) answering refusals. Groups (ii) and (iii) hold nearly all the class (b) value.
2. Predicates: the whole `where` vocabulary is 4 number bounds, presence, 4 text tests, `equals`, `not` (`C/processing-vocabulary.ts:20-29`, `parse-condition.ts`, `condition-holds.ts:56`). Every comparison is against a literal the model wrote. Core ALREADY owns a full date reader taking a `now` (`C/read-date.ts:60`, absolute and relative forms), used only for sort. A date bound is a vocabulary addition, not new machinery.
3. Core already does the right thing in four places; copy the pattern: it auto-writes layer handlers (`layer-handlers/explored.ts`), auto-writes `ensureState` and strips the model's (`script-statements/toggle-idempotent.ts:37`), restores the arrival step instead of refusing (`reachability/start-step.ts`), and keeps instructed-acts advisory. The remaining model-held duties lack such a pattern.
4. Several save-time checks are English, web-commerce vocabulary inside Core (`instructed-acts/kind-words.ts:5-12`, `script-statements/way-out-steps.ts`, `answerability/instruction-ask.ts`). They do not generalise to desktop, mobile or API clients; the refusing ones can refuse what the model cannot fix.
5. The worst refusals the model cannot satisfy are the undo/reset ledger's (3 of 8 debug runs decided, 1 contributing).

## Save-time checks: what they enforce

- `answerability/check.ts`: refuses `bootstrap.cannot_answer_instruction` when `instruction-ask.ts` reads "a set of rows" from the instruction's WORDS ("as a table", "list of", "columns"; its header lists the near misses) and the plan has no record producer or store. Skips when the node library returns no records. A false positive (the request is a write) is fixable only by adding a useless read. Fix: read the supervisor's typed `answer.kind` first; words only for single-flow builds with no plan.
- `instructed-acts/check.ts` + `kind-words.ts:5-12`: act kinds from English verbs and nouns (cart, basket, watchlist, coupon, voucher, bid, quote). Information only since t195 except the permission rule (`permission.ts`) and `optional-only.ts`. Vocabulary is web-commerce and cannot serve other clients. Fix: build the checklist from the plan's typed `lastingActs` and `consequences`; place/done words (`AUTOMATION_STUDIO_INSTRUCTED_ACT_PLACE_WORDS`) become client-supplied.
- `reachability/`: arrival compared by a 12-character prefix (`location-agreement.ts`); a missing arrival is RESTORED at completion, not refused (`start-step.ts`). Good pattern; client-neutral since the host declares the arrival action and parameter (`step-goes-to-location.ts`).
- `parameter-schema/fit.ts` (JSON-Schema fit, quotes only identifiers), `parameter-words/*` (the right line for a misplaced word), `script-statements/handler-blocks.ts` (each refusal at its line), `toggle-idempotent.ts` (names the node to use), `repeat-bound.ts` (moves the bound instead of refusing): satisfiable by the model.
- `incomplete-draft/`, `unfinished-build/`, `generation-failure/`, `authoring-result/`, `verification/`, `subflow-candidate/`: lifecycle, result records, advice memory (`repeated-advice.ts`, `disclosure-advice.ts` rewrite judge advice the build already proved unusable) and detached execution. No grammar duty found; `unchanged-submission.ts` and `kept-condition-refusal.ts` govern resubmission.

## Refusals the model cannot fix

1. Undo/reset admission (`site-reset/undo-admission.ts`, `undo-claims.ts`): a reload-causing `modify_existing` press has no witness; a stale in-place list read counts removals against unspent acts; admission says `undo_already_back` while settlement says press back (mvrj-6916, mvrj-b6dc, mvrj-a44a all ended Blocked with no Flow). Needs row 10.
2. A judged no with no grounded defect: `UNSURE_RETESTABLE` tells the builder to change the Flow "for the defect the no's reading names" (`subflow-candidate/subflow-trial-gate.ts:382-385`) even when the Flow is right (mvrj-c20c T4/T5, mvskodlp); `unchanged-submission.ts` then refuses an unchanged resubmission and a revision judged no cannot be tested again. Fix: never carry an ungrounded advice sentence forward (mvrj-c20c fix C).
3. `candidate.kept_condition_*` (`candidate/kept-condition-refusal.ts`): a condition a trial showed correct may not be dropped; if a later judge says it is wrong the model needs the one-time resend (`resend`, t650). Existence of that resend on every path is inferred from the header (not verified).
4. The repeat guard's wording "the same as before" sent a stale handle again (mvrj-b6dc R4). Wording, not structure.
5. Max 3 trials per revision and `candidate.trial_unaffordable`: by design.
6. `way-out-steps.ts` on a non-English or unlisted close label read as accepting: fixable only through the "step of its own" escape, which a model may misapply. Needs row 6.

## Top (b) changes ranked by effect

Effect = debug runs (of 8, `fhl-debug-notes.md`) where the deciding or contributing cause sits in that duty.

1. Auto-pair undo/reset from client-recorded effects (row 10). 3 runs decided, 1 contributing. Client emits an undo descriptor or `irreversible`; wrong pairing is caught by witnesses and a closed `actsUnsettleable` ending.
2. Date bounds in `where` plus an unreadable-date count in trial reads (row 2). 3 runs. Smallest change: the reader exists.
3. Relation/membership via client marks, computed discriminating field, and the t785 note promoted to a one-time refusal (row 1). 3 runs. Highest teaching risk if worded with site terms; Core computes from detection data and words it generically.
4. Core builds handlers from trial-observed interruptions (row 5) and a client `intent` per control (row 6). 2 runs plus English-list fragility.
5. Toggle: client `stateful` before a press, direction from the instruction verb, refuse a plain press on a stateful control (row 7). 3 runs touched it.
6. Required typed `effect` for lasting-act parts, count defaults from the quote (row 9): more parts get a Core proof.
7. Paging add/require and `done when` as a read bound (row 13): generality, no failing run.
8. Number/text-test mismatch refused at save (row 3) and cross-field compare (row 4): low evidence, moderate cost.
9. Replace English word lists in `instruction-ask.ts`, `kind-words.ts`, `way-out-steps.ts` with the plan's typed fields and client flags (rows 6, 17). No web run is blocked by them; required before a non-web client.

## Risks

- Vocabulary additions change Core's contract and the downstream web twin together; `AUTOMATION_STUDIO_RECORD_VALUE_READING_CASES` must gain date-bound cases. `within` is time-dependent and needs a run-time `now`; absolute dates do not.
- A computed "discriminating field" hint can mislead on a 3-row sample by accident. Word it as evidence, and only when it separates kept from left-out on every sample.
- Auto-paired undo can undo more than the build created (mvrj-6916). The ledger's "this build's own acts only" rule stays the gate.
- Auto-written keys cost a regression once (an undeclared `ensureState` resolved to `expectedState`, t775-P). Only write keys the node declares.
- Required `effect` adds a refusal the supervisor cannot satisfy for read-only parts; require it only when `lastingActs` is non-empty.
- Judge nondeterminism (identical prompts flipped, mvswewhy 0057/0059) means any rule relying on judge frequency is unsafe; the (b) changes move evidence into Core so fewer questions reach a judge.
