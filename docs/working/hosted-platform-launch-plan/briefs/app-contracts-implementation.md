# Standard custom-app shared contracts
Role: standard worker, existing gpt-6.1-sol configuration; no delegation/git/shared-doc edits.
Goal: implement browser-safe versioned app manifest/install/operation contracts from app-frontend-contract-discovery.md, then freeze the public schema for the durable Core kernel.
Own: packages/contracts/src/apps.ts and apps/** with owning tests; contracts package.json only additive ./apps export; own report app-contracts-implementation.md. Lead owns other public barrels/version integration.
Read: plan Current State; app frontend discovery; paired plan Standard Custom-App Frontend Contract; existing FluxNode type-schema/canonical/spec/hash/run types and contract conventions.
Must not touch: other contract schemas, IAM/actions/generated files, Core/web/SDK/extension/source outside ownership, shared docs/git. No builds or dist mutation.
Use @fluxiq/contracts/apps as additive subpath; Node SDK root remains unchanged. Export manifest/install/operation/error types and strict parsers/validators through cohesive modules/barrels. No Node/Buffer/process/fs/credential-chain imports; Web Crypto digest operations are permitted.
Manifest v1: publisher/app/version, separate immutable package and canonical-manifest digests, frontend entry, exact allowed origins/redirects, named typed operations, requested grants, required runtime/environment/callback capabilities and explicit update policy. Never accept publisher-supplied verification as authority.
Operations are query versus execution, with existing JsonTypeSchema input/result types and an opaque pinned backend binding (kind/id/definition digest); no executable source or arbitrary panel/FluxNode options. Business inputs remain data, not identity/tenant/payer claims.
Permissions are closed, typed, resource/binding-scoped requested capabilities (dataset read/write, secret use, network origin, automation execution as needed); no wildcard grants, secret values or private credentials. Reuse existing effect/capability vocabulary where compatible; keep any new app vocabulary explicit.
Installation is server-owned opaque id, workspace, immutable app pin, approved grants, explicit target/environment and payer policy, installer, generation/revision, active/revoked status. Do not infer paid cloud or widen grants on upgrade.
Invocation outer envelope is installation/operation/typed inputs/idempotency identity only; auth comes from a trusted adapter, never body role/workspace/payer. Operation resolution is not an accepted-run receipt; no execution-success stub.
Digest verification must be deterministic, exclude its own digest field, distinguish package digest, reject tampered content and unsupported versions; parse errors must not echo supplied secret values. Origins/redirects reject wildcard, credentials and inappropriate schemes; define explicit loopback development handling without silently permitting arbitrary HTTP cloud origins.
Tests cover strictness/unknown fields, duplicate operations, invalid binding/digest, canonical equivalence/tamper, origin/redirect exactness, unsupported version, safe metadata and reuse of existing JSON type validation. Browser dependency safety must be mechanically checked from the new entry.
Before broad implementation send concise chosen public shape/export names and unresolved choices to lead; proceed with clear decisions. Signal stable source when done. Run only source-local owner tests/type probe; coordinate with web worker/lead before package builds. No full suite/server/browser/provider.
Return frozen interface, exact tests/results and limits, report path and standard return contract. First unit is contracts, not a claim that installs/auth/invokes already exist.
