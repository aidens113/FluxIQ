# Hosted connection activation and privacy integration

Outcome: Done for read-only discovery. Recommendation: implement the complete privacy boundary first, without exposing PKCE start in production UI. The smallest complete privacy unit includes the shared admission authority, inert content/MAIN startup, every current tab/command/recording consumer, the global visible-capture barrier, and restoration-risk handling. A registry call or filtered tab list alone cannot supply that boundary. Selected-binding connection/outbox/HTTP and safe revocation composition follow before hosted UI activation.

## Proposed stable admission interfaces

Reuse the prior proposed narrow port, implemented behind existing authentication-tab ownership rather than a second owner map:

    AutomationTabAccess {
      project(privateBrowserCandidate): TabAccessDecision;
      inspect(tabId): Promise<TabAccessDecision>;
      revalidate(lease): Promise<boolean>;
      current(lease): boolean;
      destination(url): "allowed"|"excluded"|"unavailable";
    }
    TabAccessDecision = {kind:"admitted", tab:ReadOnlySummary, lease:OpaqueTabLease}
                      | {kind:"excluded"|"unavailable"};

The adapter privately binds global privacy generation, browser session, tab/document epoch and connection-owner generation. Leases are minted opaque objects, never accepted from requests or persisted. Revalidation must not switch identity or target. Check current() synchronously after the final await and before the actual browser/page/persistence/send operation. A claim followed by release still invalidates older results. Candidate committed/pending URL inspection occurs only inside this privileged classifier; excluded owned IDs are refused before URL/title getters are touched. Content itself must read no page-owned fields before admission. destination() classifies intended ordinary navigation before tab creation/update/reload or served-status requests; it grants no tab authority and cannot turn a caller-supplied candidate into a lease. Driving an existing target still requires its valid lease. Privileged auth navigation uses the separate launch permit.

Add ID-only registry observations ownership(tabId): unowned|excluded|unavailable, captureBlocked(): boolean including reservations/owners/loading/failure, and trusted route replacement through the privacy owner. Registry lifecycle mutations advance privacy generation synchronously. Production passes PKCE a wrapper implementing its unchanged ready/own/owns/sessionIdentity port, so its own() also reserves privacy and invalidates leases. Do not expose raw own/release to ordinary command or content callers.

Give content a separate data-free admission handshake, preferably a privileged runtime Port whose sender supplies real tab/frame/document evidence. Proposed hello is only type/version/contentInstanceId; reply is admitted with opaque grantId/instanceId, or excluded/unavailable. Do not reuse RecordingEventPayload with fake empty URL/title fields. Bind grants privately to sender/document and background generation. Missing frame/document proof must refuse or use an explicitly proven browser-specific document-epoch adapter; never trust caller fields. Port disconnect/new worker/document lifecycle requires fresh admission. Delayed old grants cannot reactivate a suspended instance. Every page payload includes its current instance/grant, and background validates it before touching/caching the payload.

Admission activates isolated observers/recording/actions and optional MAIN observation for that document. Suspension must synchronously stop capture, discard pending input/mutations/continuations without flushing, remove observed dialog evidence and clear retained request state. Existing recorder.setRecordingState(false) flushes pending input and is therefore not a privacy-suspension primitive. All descendants inherit top-tab refusal. MAIN flags/events remain page-controlled hints, never authorization or secret-bearing channels; forged DOM signals cannot make isolated/background consumers accept data. Gate all MAIN entry probes, not only prompt, and keep native pass-through semantics while inactive.

## Global visible-capture barrier and lifecycle

While any owned/reserved or uncertain authentication tab exists, refuse captureVisibleTab entirely. Do not call it and discard afterward. Checking requested/active tab IDs before or after capture cannot prevent auth-pixel acquisition during a user-focus race. This is temporary sensitive-page screenshot exclusion; it is never a default connection/key lock. Admitted ordinary DOM reads/actions/recording continue without visual evidence and with an explicit privacy-unavailable visual result.

Proposed owner-only port is beginAuthentication(): Promise<OpaqueAuthLaunchPermit> and runVisibleCapture(tabLease, operation): Promise<{kind:"captured",value,captureLease}|{kind:"excluded"|"unavailable"|"stale"}>. Capture callbacks belong only to the guarded capture owner. beginAuthentication must close new capture admission and advance generation synchronously before its first await, durably write a private nonsecret restoration-risk record, and await already-started browser capture calls draining. Only then may the browser tab adapter create/navigate/activate an auth surface. A failed risk write/claim/drain issues no launch permit and cannot navigate. An in-flight capture finishing during that transition is discarded before decoding/serialization/hash/cache/persistence/upload/forwarding; draining is required because discard cannot undo browser-memory acquisition.

The browser adapter then creates inactive blank, commits exact ownership, suspends/invalidates any old content grant, verifies session/owner/current generation plus launch permit again after awaits, and only then navigates. It can focus the auth tab only after this barrier. Existing PKCE signatures remain unchanged. Known auth routes remain excluded even without an attempt. Auth-created child tabs/windows must stay private; classify opener IDs without exposing metadata, and keep unknown arrivals unproved during sensitive/restoration risk. No delayed creation gets admission merely because it arrived later.

Keep owned auth surfaces private after PKCE terminal, as the protocol already requires. A separate privileged lifecycle owner may close/scrub only exact current-session owned surfaces, never guessed numeric IDs or unrelated work. It must not clear global capture exclusion merely because token exchange/cancel finished, the parent tab disappeared, or a route now looks ordinary. Outstanding children/uncertain surfaces retain risk. Clear risk only through a proved cleanup transition; missing evidence remains explicit uncertainty.

Register privacy listeners before getConnection/autoconnect/page refresh or content handshake handling. New startup begins closed; await registry and private risk hydration. Same browser session restores exact owners and PKCE waiting only after fresh checks; exchanging is uncertain/no repost. On browser-session loss, old IDs and secrets are not authority. A persistent nonsecret risk latch must survive session storage loss; registry/attempt stores alone cannot supply it.

When an earlier sensitive surface may survive but cannot be correlated, quarantine all unproved tabs, including delayed restore/onCreated arrivals. Admit only a fresh internally created ordinary automation tab whose returned ID is proven under the current generation; create it blank and validate/admit before ordinary navigation. Never copy a quarantined URL/query/fragment to manufacture a clean tab. Keep existing tabs open, and keep authenticated transport/model use usable. Global visible capture remains refused while unresolved auth might be active. This is conditional recovery from actual risk, not a permanent all-existing-tabs rule after any sign-in. No source evidence proves portable cross-browser external-tab restoration identity; do not silently label it solved. Unrestricted old-tab reuse remains blocked until a tested recovery policy provides real evidence.

User/manual navigation can change browser state outside the controlled launch barrier. Classify route changes conservatively and invalidate outputs immediately; do not claim an extension precheck atomically prevents every browser-memory acquisition during arbitrary external navigation. Provider-free browser proof must establish the supported boundary, including cached/restored documents. Native identity has already failed this privacy purpose and is not a fallback.

## Selected-binding transport, owner state and revocation

Hosted connection construction must consume one immutable selection plus a checked private snapshot. Fixed socket gateway comes from snapshot.binding.gatewayUrl, hello.clientId from snapshot.installId, and tokenStorage from createHostedCredentialTokenStorage({repository,snapshot,isCurrent}). Omit legacy hello.token on this branch so it cannot bypass the adapter. Keep the existing local/enrollment constructor path explicit; bootstrap must not overwrite hosted installId with the global client ID. Only actual session_ready after durable rotation persistence means connected; PKCE progress is separate safe status.

Replace hosted mutable CoreApiCredentials usage with a background-private immutable HTTP lease carrying one selected binding/owner generation, current proof and pinned HTTP destination. Proposed exact lease port is acquireHostedHttpLease(): Promise<HostedHttpLease>, where the frozen lease has checked binding, ownerKey (= snapshot.lineageKey), credential, expiresAtMs and current():boolean. It is minted only after actual repository read/scope validation, never accepted over a request or persisted as authority. This secret-bearing lease is confined to background HTTP helpers, never a panel/status/log payload. Capture it before an operation starts, revalidate before credentialed fetch and after awaits, reject credentialed redirects, and refuse stale results before parsing/adopting into current state. Never re-read new profile credentials at the end of an old screenshot/trace/project operation. Apply this to program/chat/diagnostics/project/recordings/state-assets/trace/revoke helpers. Profile controls accept selected origin/id, never request-supplied token/gateway/owner authority. Keep the existing explicit local CoreApiCredentials branch compatible rather than casting it to a hosted lease.

Use actual snapshot.lineageKey as namespace: it binds checked audience, install, user, workspace, connected client and trust lineage. Use a scoped ClientGatewayStorageArea/store adapter for outbox, in-flight, seen-command and host leases, retaining Core's queue/loss primitives. New trust/new owner gets a new namespace and fresh per-connection state; normal reconnect/rotation keeps it. Before retiring old owner, synchronously invalidate generations, stop old intake/commands/captures/sends, checkpoint old queue/held loss with awaited Core setLineage(currentLineage), and retain failed old checkpoint state. Do not relabel owner/privacy discard as count/budget loss or replay old queue into new scope. Reset project adoption, recording/navigation/click/extraction/activity/overlay, global automation-tab/history/readiness/look/frame/timer caches. Late callbacks may not write or publish into the new owner. Existing local default keys/behavior remain compatible.

Core source finding: apps/web/src/server/connect/revoke.ts:9-17 accepts current/previous/obsolete proved credentials (only invalid/inactive return), then revokes the complete binding.trustedClientId. service/access.ts::revokeTrustedClient ends that trust/current sessions. trusted-clients.ts::issueApproved/createClient gives fresh consent a new UUID and revokes same-install old trust; ordinary credential rotation retains trusted-client identity. Therefore a stale predecessor proof can revoke the currently active rotated trust. A client-side read followed by unconditional queueRevocation or HTTP is not an atomic safety fence.

Before dispatch, extend private intent metadata with proved connectedClientId/lineage/cause and use a durable repository retirement fence. In one IDB transaction: exact-revision forget removes only its matching active trust and records retirement/intent; unadopted cleanup records retirement only when no active same-target client exists. Commit/rotation must refuse a retired target, preventing same-client adoption between safety check and HTTP. Fresh consent's new UUID is independent. Newer same-client revision conflicts stay cleanup_required; never retire/queue an adopted predecessor automatically. Unknown legacy intents without safe target metadata stay quarantined. This is a proposed repository interface change, not an existing guarantee.

Suggested dispatcher input is an opaque repository-issued dispatch claim containing pinned checked audience, target trust generation, intent ID and private proof. Claims exist only for retired targets and cannot be supplied by UI. Dispatch fixed /connect/revoke JSON schema with required extension header, credentials omit, redirect error, no-store/no-referrer. Acknowledge only that exact claimed intent after actual validated 200; 503/lost response retains intent. Do not sweep old local pendingForget through hosted dispatch or queue cleanup over a replacement socket. No new Core wire API or credential scheme is required for this retirement-fence approach, but root must freeze it after repository review before enabling dispatch. The existing protocol intentionally sends no revoke HTTP.
