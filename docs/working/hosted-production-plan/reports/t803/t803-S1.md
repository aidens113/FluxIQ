## Decisions to review
- list-recordings: projectless call lists every recording in the workspace, so it is decided on the workspace and NOT item-filtered (no `list`). Reason: typed-store summaries for a project page may lack `metadata.projectId`, so a per-item ref would hide a project-only reader's own rows. Workspace-wide content named here, as the brief asked.
- `projectId` is optional in RecordingProjectRequest (create/update/delete/append/finalize/normalize recording, get-recording, get-proposal etc.) and the service supports project-less recordings. These use project()/projectChild(): a call without projectId gets a sentinel resource (no owner), so only full-access callers can do it. Intended-safe, but project-less recorder use by an owner-conditioned user would now be refused.
- Optional flowId: list-flow-instructions, get-flow-instruction-set, list-flow-change-proposals -> project() (flowId optional). Required flowId -> projectChild("flow"). Subflow endpoints use the Flow (no subflow child kind); list-flow-subflows(-targets) also projectChild flow.
- delete-recordings (recordingIds array), delete-proposal, get-proposal, approve/review proposal, mine/learn/propose evidence, normalized-timeline reads, pipeline artifacts, artifacts: project().
- No `creates`: create-flow, create-recording, create-flow-subflow are children of a project.
