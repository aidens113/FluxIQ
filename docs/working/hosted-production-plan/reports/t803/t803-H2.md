## What changed and why

**New module `apps/web/src/lib/app-route-iam/`** (beside `operational-route-contract.ts`, with a barrel):
- `types.ts`: the types of the contract table. They are derived from `GlobalProgramApiRegistry["authorize"]`, so the table and the registry cannot drift apart.
- `contracts.ts`: `APP_ROUTE_IAM_CONTRACTS`, the single route table (below).
- `registry-decided-routes.ts`: `APP_ROUTES_DECIDED_BY_REGISTRY`, which lists the program route.
- `contract-for.ts`: `appRouteIamContract(method, path, variant?)`. It throws `Unclassified app route: ...` for a route that is not in the table. Each route resolves its contract when its module loads, so a route missing from the table fails at load time.
- `authorize-app-route.ts`: `authorizeAppRoute(api, contract, caller, actor, input)`. It sets the actor's `channel` from the caller, builds the resources with `contract.resource.of(input)`, and calls `authorize`. It returns `null` when allowed. Otherwise it returns `{status, error}`: 401 for `authorization.required`, and 403 for a deny or a failure to decide.
- `panel-actor.ts`: `panelRouteActor(auth)`, an actor with `channel: "panel"`.
- `paired-client-route-actor.ts`: `pairedClientRouteActor(identityAccess, session)`, which uses `pairedClientActor` with the identity snapshot.
- `route-param-id.ts`: `routeParamId(value)`, a URI decode that never throws.

**`operational-route-contract.ts`**: the disposition table remains, but each operation now carries `iam` (its entry from the IAM table, bound when the module loads). I removed the old `permission` field and `canUseOperationalRoute`. Their only users were the three framework routes and one test.

**`program-route.ts`**: `pairedClientActor` now returns `channel: "paired-client"`.

**Routes**: every `permissions.includes` and `canUseOperationalRoute` call is replaced by `authorizeAppRoute(fluxiq.programs.api, ...)`. Each route returns its existing refusal shape `{ ok: false, error }` with the same status. The decision sits where the permission check was, so validation statuses (400/404/415/413) are reached in the same order. Routes that accept a paired client's token (snapshot, trace artifacts, recordings, state-asset upload) now build the approver's actor with `pairedClientRouteActor`. The program route's panel actor now sets `channel: "panel"`.

### Decisions

1. **Routes that checked no permission ("none")** need a workaround, because `authorize` always takes a permission and `local` decides by it. For these routes, `authorizeAppRoute` passes `permission: "programs.read"` and adds `programs.read` to that one decision's actor. As a result, `local` and `self-hosted` allow every authenticated caller as before, `service` decides by policy alone, and a paired client's session policy does not narrow it below today. All of this lives in one constant, `AUTHENTICATED_ONLY`, so it can be removed in one place (see Open questions).
2. **The pairing reference never goes into an FRN.** It is what approves a browser, and the audit keeps FRNs. Approval binds the browser to the caller only, so it acts on the caller's own user. Dismissing a pending pairing, which no one owns yet, acts on the workspace.
3. **A browser is identified by `trustedClientId`** (plan, Resources: `gateway: browser/<connectedBrowserId>`), not by the gateway session id.
4. **Framework programId.** Framework operations use programId `framework` (FRN `frn:fluxiq:ops:<ws>:program/framework`), which `FluxIQServiceGuardrail` denies on service.
5. **The program route is not decided twice.** `call()` already decides and audits; deciding again in the route would double both. It only sets the channel.
6. **Route-param ids** go into refs through `routeParamId`, which never throws. A malformed param becomes an id that no one owns, and the decision happens before the route's own decode and validation, as the permission check did.

## Open questions and contradictions

1. **Registry change needed: `authorize` with no permission.** `ProgramApiAuthorizeInput.permission` should accept `null` (or be optional), meaning that `local` and `self-hosted` allow any authenticated actor. That would replace the `AUTHENTICATED_ONLY` workaround in `authorize-app-route.ts`, which is used by snapshot, trace artifacts, recordings, the program directory and the token upload.
2. **Policy gaps on `service`, outside my ownership (`packages/fluxiq/**`).** `FluxIQUserAccess` currently refuses a hosted user these app routes, which the hosted panel will likely need:
   - `gateway:ApprovePairing` and `gateway:SetAutomationStudioContext` on the user's own `user/${PrincipalId}`, so a user can pair their browser and clear their context.
   - `gateway:PutTraceArtifact` on their browser. No `browser` owner resolver is registered (only `project` and `key` are), so every browser ref has no owner and is denied.
   - `studio:ListPrograms` on the workspace.
   - A per-user filter for recordings and the gateway snapshot, which today are unfiltered lists across the workspace. Refusing those two is correct until they are filtered.
3. **Behaviour change: tokens whose approver is gone.** On snapshot, trace artifacts, recordings and the state-asset upload, a token whose approving person is disabled or gone, or whose session has no `operatorUserId`, is now refused 401. Before, any valid token was accepted, because those routes built no actor. This matches the program route's existing rule ("disabling a person takes their paired clients' reach with them").
4. **Route actions are not in the generated catalog.** The catalog only has `endpoint` sources, so these actions appear in no catalog listing or predefined policy until the catalog gains a route source.
5. **Test placement.** The shared route fixture and the two multi-route tests sit in `apps/web/src/app/api/tests/`, the `tests/` folder of the nearest directory containing all their subjects, per the test-placement rule. That folder is not literally "beside each" route.
6. **Line endings.** My Python edits briefly turned CRLF working files into LF. I converted all 40 touched and new files back to CRLF. The index is LF either way, so content diffs are unaffected.
7. **Shared build output.** I rebuilt `packages/fluxiq/dist` and `packages/contracts/dist` (build output only, no source), under the lock, because the web tests refuse a stale dist. Any agent that later edits Core source will need another rebuild before running web tests.
