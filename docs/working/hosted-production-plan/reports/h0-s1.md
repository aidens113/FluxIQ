# H0-S1 (= downstream D0): does a tab-based sign-in (Flow A) complete with the extension observing `/connect/done`?

**Answer: yes, in Chrome 156, Edge 156 and Firefox (Playwright build 1475).** A top-level
`tabs.onUpdated` listener, with only the `tabs` permission and `<all_urls>` host permission the real
manifests already have, saw `/connect/done#code=..&state=..` in every case below, including after
the background worker or event page had been stopped, and in a tab the extension did not open.

## Method
- Stub server `spikes/h0-s1/server.mjs` (127.0.0.1:47101): `/connect/authorize` redirects to
  `/connect/done#code=<32 random bytes>&state=<query state>`; `/connect/done` sends
  `Referrer-Policy: no-referrer`, `Cache-Control: no-store`, loads nothing. Not a Lab scenario.
- Spike extensions `ext-chrome` (service worker) and `ext-firefox` (event page): the real dist
  manifests' `permissions` (alarms, activeTab, downloads, scripting, storage, tabs, webNavigation,
  sidePanel on Chrome) and `host_permissions: <all_urls>`; no content scripts.
- Background: `startFlow` -> `tabs.create(authorize)`, pending `{state, verifier, tabId, startedAt,
  ttlMs}` in `storage.session`; top-level `tabs.onUpdated` (registered at evaluation) accepts only
  origin `http://127.0.0.1:47101` + path `/connect/done` + matching `state` + unexpired pending, in
  any tab; records the verdict with a timestamp and a random per-boot id to `storage.local`; closes
  the tab. Each worker start appends a `boots` record, so a new boot id proves a restart.
- Drivers: `run-chromium.mjs <chrome|msedge>`, `run-firefox.mjs`. All headed, temp profiles, one
  browser at a time; all browsers and the server closed afterwards.

## Loading the extension (finding)
- Branded Chrome 156: `--load-extension` is ignored (probe: `serviceWorkers: []`).
- Works: launch the browser myself with `--remote-debugging-port=47110 --enable-unsafe-extension-debugging`,
  `chromium.connectOverCDP`, then browser-level CDP `Extensions.loadUnpacked {path}` -> returned an
  extension id, SW appeared. Same on Edge 156. No fallback to Playwright Chromium was needed. A pipe
  was not required. (`launchPersistentContext` cannot do this: it exposes no browser-level session.)
- Firefox: spawn the Playwright firefox-1475 with `-start-debugger-server 47120` and prefs
  `devtools.debugger.remote-enabled`, `devtools.chrome.enabled`, `devtools.debugger.prompt-connection=false`,
  `xpinstall.signatures.required=false`; RDP `root.getRoot` -> `addonsActor`, then
  `installTemporaryAddon {addonPath}` -> `{"addon":{"id":"h0s1@example.local"}}`. Worked first try.
  Tabs are opened by re-invoking `firefox.exe -profile <p> -new-tab <url>`; pages are steered by the
  stub server (302 to the done URL with the pending state) and the extension POSTs its records to
  `/report`, so no Playwright is involved.

## Defects found in my own listener (carry into the real one)
1. `tabs.onUpdated` fires twice per navigation (`changeInfo.url`, then `status:"complete"`); the first
   draft handled both: rejected cases were recorded twice, and accepted ones raced, with
   `tabs.remove` rejecting `No tab with id` because the other invocation had already closed it.
   Handle `changeInfo.url` only, and make the accept idempotent (claim the pending record once).
2. `tabs.remove` on an already-closed tab rejects; treat it as closed.
3. The real `tab-flow.ts` must act only on the first `changeInfo.url` with a match, and clear pending
   before the token exchange so a replay finds none.

## What it changes in the plans
- **D0 passes.** The `tabs` permission suffices (no `webNavigation`, `identity` or content script is
  needed for this); listener must be top-level and synchronous in the worker/event page.
- Downstream plan "accept `/connect/done` in a tab it did not open" is confirmed workable; keep the
  state + exact-origin + unexpired checks (all three negatives held).
- Add to the downstream plan: dedupe on `changeInfo.url` only; `storage.session` is the right home
  for pending (survived worker stop on all three browsers).
- Not exercised: natural >30 s Chrome idle stop (forced with `Target.closeTarget`; Edge/Chrome woke
  and handled it); cookie/consent UI; token exchange; a real Chrome profile with the Chrome Web Store
  build (unpacked, temp profile only); `webext` signing of a real Firefox build.
