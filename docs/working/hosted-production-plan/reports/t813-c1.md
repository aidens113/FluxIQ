## Design decisions (supervisor)

- **Tenancy follows the profile.** `local` and `self-hosted` are single; `service` is multi.
  - The primary workspace is `FLUXIQ_WORKSPACE_ID ?? "workspace-main"`. It is built exactly as
    today, is never evicted, and `getFluxIQ()` returns it. Under single it is the only entry.
- **Layout v3, adjusted from the plan to avoid nesting storage roots.**
  - `dataRoot` is the primary's host root.
  - Platform data stays in its `.fluxiq`, as today; that folder already holds `platform/`.
  - Tenants live in `<dataRoot>/workspaces/<id>/`, each with its own `.fluxiq`.
  - Why not the plan's layout: `programs/_shared/state-root.ts` resolves a store to the nearest
    `config.json` above it, so tenants inside the platform's `.fluxiq` would break.
- **Provisioning stays single tenancy.**
  - Under `service`, every user still resolves to the primary until C2 and C3 move the call sites
    and flip it.
  - The manager already routes N tenants through platform memberships.
- **IAM on `service`.**
  - Every entry gets a lazy `source`, which is `workspaceIam(id)`.
  - It also gets the platform's `BufferedIamAuditSink`, behind a bounded deferred sink that drops
    the oldest record when full.
- **Background tasks.** A workspace is pinned only by a task run in progress, or by an enabled,
  interval, non-`maintenance` task among the loaded ones. A workspace that was never loaded runs
  no schedules, as today.
