## What lane A now does

- **Profile resolution.** `packages/fluxiq/src/platform/profile/`, a pure, edge-safe package export
  `fluxiq/platform/profile`. `resolveFluxIQDeploymentSettings(env)` resolves everything else from
  `FLUXIQ_PROFILE`: the public origin, the gateway bind, the `wss` URL, the allowlist, the limits,
  `FLUXIQ_TRUST_PROXY`, the drain time, the session cookie name, the setup code file and the log
  format. `resolveClientAddress` trusts only the rightmost `X-Forwarded-For` entry, and only behind
  a trusted proxy. `clientAddressPrefix` gives a /24 or /48.
- **Gateway transport** (`apps/web/src/server/client-gateway-websocket.ts` plus the
  `client-gateway-websocket/` folder):
  - the contract's Origin grammar, with `moz-extension://*` matched by prefix, the N7 rule for a
    missing Origin, and no start on a public bind without a valid allowlist;
  - the frame cap is checked against the declared length, before anything is buffered (close 1009);
  - the hello deadline and the per-socket token bucket both close with 1008;
  - the peer address goes into `connect`;
  - `beginDrain` sends `server.going_away`, and `openConnectionCount` reports open sockets;
  - a half-open socket leak that hung `server.close()` is fixed.
- **Gateway service** (`client-gateway/service/`):
  - the peer is kept on the session, and the audit carries only its prefix;
  - pairing codes come from `crypto.randomInt`;
  - pending pairings are capped (1,000 in total, 5 per address on public profiles);
  - ended sessions are pruned to 1,000;
  - the audit is a ring of 10,000;
  - `onSecurityEvent` and `recordTransportEvent` are added, and security listeners never receive
    pairing codes.
- **Runtime** (`lib/fluxiq.ts` plus `server/{drain,log,readiness,security-audit,startup}`):
  - the settings drive the gateway, and the bundle path is set by `FLUXIQ_GATEWAY_SERVER_MODULE`;
  - status omits host paths under `service`;
  - the provisioning listener starts only under `service` when both `FLUXIQ_PROVISIONING_LISTEN` and
    `FLUXIQ_PROVISIONING_TOKEN_FILE` are set, and closes first on shutdown;
  - `FLUXIQ_EMAIL_SENDER` accepts `none`, `file` or `file:<dir>`;
  - SIGTERM drains;
  - `/api/health` and `/api/ready` are added;
  - logs are JSON lines with secrets redacted;
  - gateway security events go to `.fluxiq/security/gateway-audit.jsonl`, rotated at 10 MB, on
    non-local profiles only;
  - the owner claim is announced by its file path, never by the code.
- **Owner claim** (`server/owner-claim/`, `app/setup/`):
  - the one-time code comes from `FLUXIQ_SETUP_CODE_FILE` or is generated (160 bits, file mode
    0600) and compared by digest;
  - wrong codes are throttled;
  - the owner is created through provisioning with `FluxIQOwnerFullAccess` by the in-process
    caller, and a retry is idempotent;
  - the default admin is retired: deleted while its password is still `admin`, otherwise disabled;
  - `/setup` answers 404 on `local` and once claimed.
- **Cookies and throttles:**
  - `lib/session-cookie/` names the cookie `__Host-fluxiq_session` on an https origin, and logout
    clears it with the same attributes;
  - the panel-wide lockout is removed, and a warning is logged at 100 failures in its place;
  - admin/admin is refused (`setup_required`) on non-local profiles;
  - the welcome, reset-request and reset-submit forms are throttled.
- **Middleware and discovery:**
  - `/.well-known/fluxiq` is rewritten to `/api/discovery`, which serves a document validated by
    the contract and cached for 5 minutes;
  - cookie-carrying writes from another site or origin are refused; Bearer requests are exempt;
  - the three operator endpoints that recheck no credential are refused on public profiles.
- **Docs:** `SECURITY.md` gains a "Hosted Deployment Boundaries" section, and
  `docs/integrations/client-gateway-websocket.md` is updated. The framework reference was
  regenerated by `pnpm docs:reference`, because the public surface grew.

## Decisions taken (supervisor; the lead can overrule)

- On `local` the frame cap is 256 MiB rather than unlimited, which is above anything a real client
  sends. Local has no hello deadline, rate limit or per-address cap.
- Security listeners and the persisted gateway audit never see pairing codes. The in-memory snapshot
  keeps them, as before.
- The per-address pairing cap keys on the full address, not the prefix.
- The setup code file's path is printed at first start; the code itself is never printed.
- The provisioning listener starts only under `service`, per the brief, so a self-hoster's own
  sign-up site cannot use it yet.
- `ClientGatewayService` now has 38 methods (the audit fails at 40), so the next addition needs an
  extraction first.
