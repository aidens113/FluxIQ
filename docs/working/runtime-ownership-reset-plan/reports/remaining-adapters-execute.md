With Root's narrow writer release, `descriptor.ts` now rejects each Proxy before either descriptor or prototype reflection. Four immediate regressions cover actual entered own/inherited/revoked Proxy refusal with zero traps and pending/reopen, and the unchanged original unobserved Proxy `get` receiver/result. - `execution-admission/kernel/{clock,observed-clock,failure-clock,ports}.ts` and `kernel/callback/{clock,property,unknown-sync,frame,from-observation}.ts` use the original private source and parent. Successful arbitrary data clocks use the existing sync callback port and retain a gap; throwing callbacks retain unknown. Diagnostic fallback fences the observed execution and preserves the original action fault; it confers no completion proof. `stalled_build` owns the separate `node-execution/failure.ts` legacy/observed split and its immediate legacy regression.
- The observed custom clock's historical nullish-result fallback remains native, after the original custom call is accounted. Two explicit nullable-result cases assert one custom call, a numeric fallback and pending/reopen; neither declares the custom clock pure.
- `AutomationExecutionPorts` returns the exact original port object. Descriptor validation happens at every selected retained method, including after awaits and during timer cancellation. It does not proxy, bind, register or replace ports, and existing concrete-owner admission checks remain intact.
- `runtime/environment/{clock-bindings,scoped,wait,within}.ts` and its barrel retain unobserved late virtual-clock property lookup. Private immutable binding facts can only refuse changed delegates; calling `bind` twice cannot replace the factory's original fact. Those facts never declare a callback pure or complete. Only the exact immutable canonical live forwarding `within(work) => work()` and native-wait `delay` retain their existing canonical path. - Scoped `within` selects the original `clock.startTimer` before entering its work and stores that exact callable in the existing channel scope. A getter installed after an awaited work predecessor is not read at the later timer boundary: the selected original function remains in the scope. The surrounding scoped wrapper is still unsupported unless its actual original source contract supports it, so its metadata does not certify that timer's effects.
