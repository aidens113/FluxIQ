# Client session metadata

Client approval establishes usable client authority. Model configuration availability is separate: normal connections, reconnects and saved Flow execution do not require a second password, PIN or unlock. Ending the approving panel session does not revoke an independently authenticated client. Explicit client revocation and current account, tenant and IAM checks still apply.

`ClientGatewayServiceOptions.sessionMetadata` is a server-owned provider for ordinary trusted clients. `FluxIQOptions.clientGatewaySessionMetadata` forwards it through runtime construction. Its input contains the authoritative trusted-client id, owner id and client type, never a token or client-selected workspace. It returns current user and workspace summaries. An omitted provider retains generic local behavior; a configured provider that refuses or fails cannot silently fall back to local pairing. Managed-host applicability comes from the authoritative trust record.

The hosted web application supplies a provider closed over the workspace selected during tenant construction. It checks the current primary identity, active platform account, existing workspace and current membership. It does not require the original panel session or select the user's default workspace again during reconnect. Display name and email come from the account. Workspace records currently have no descriptive name, so the actual workspace identifier is the explicit display-label fallback.

The gateway owns credential expiration. Ready frames use the expiration of a successfully persisted registry credential, not a browser timer or a value supplied by the metadata provider. Registry reads wait for pending mutations; final checks reject changed session, trust, ownership, domain or credential. External identity callbacks do not hold the registry mutation queue, so revocation can proceed while they wait.

The websocket client's optional second `tokenStorage.write` argument carries a detached copy of the actual ready metadata, excluding the token, plus the envelope message id. The token remains its first argument. The client awaits this write before acknowledging receipt, publishing readiness or processing subsequent incoming frames. Storage failure is terminal for that connection and does not expose raw storage errors or credentials. Existing single-argument local consumers remain compatible.

The extension's private credential repository, authentication-tab registry and hosted storage adapter are separate foundations under integration. Their existence does not mean hosted PKCE initiation, account switching or browser lifecycle/privacy acceptance is complete. Neither this protocol nor a connection-ready frame authorizes marketplace app operations or paid cloud execution; those require their own current installation, tenant, runtime and payer admission.
