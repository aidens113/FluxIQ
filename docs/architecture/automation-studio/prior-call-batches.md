# Prior-call batches

Core offers core.run_nodes with {calls:[priorCallId,...]} only when the current
loop has eligible prior node executions. The ordered ids select exact original
executions. They supply no replacement parameters, permission claims or safety
flags. This tool does not author Flow steps or establish whole-Flow acceptance.

An original needs a positive actual dispatch receipt, successful final outer
settlement, canonical registered definition/version, concrete parameters and
explicit effective inputs, plus private host subject and resource provenance.
Its original public call must contain only the ordinary node-call fields and
an explicitly empty consequences array. Missing declarations, lasting classes,
write/replay/undo/reset controls and unaccounted inputs remain ineligible.

Both the current registered effect and the actual settled permission assessment
must be observation or explicitly repeat-safe state without effective lasting
consequences. Core never obtains these facts from model JSON, restored draft
inputs, capped declaration history or a successful-looking result alone.
The current NativeRuntime resolver supports parameter-dependent effects; nonempty
effective node-port inputs remain unproven until a trusted resolver accounts for them.

Private action-permission observation starts before declaration parsing and
settles before the history limit. It preserves the full trusted effect, including
commit with no projected classes and explicit state repeat safety. Nested and
auxiliary checks aggregate; denied, malformed, unfinished or unknown checks
cannot become safe merely because a later check succeeds. A matching primary
assessment must belong to the actual outer tool/call. Auxiliary safe reads alone
do not prove an unchecked main execution.

Capture observes ordinary permissions without vetoing. Selected execution adds
a deny-only preflight before permission can grant or ask, and checks fresh primary
proof again before acknowledging its opaque capsule. Stronger, unsafe or unknown
actual effects are held. Neither acknowledgement nor a returned JSON status proves
dispatch. The host producer reports fresh final-lowered main attempts through the
selected execution accessor; the model cannot submit that report.

The same wrapped executor and ordinary current admission, permissions, retries,
uncertainty, quota, cancellation, deadline and purse rules apply to each member.
Batch intent bypasses only the original successful answer-cache entry. It never
repositions, replays a prefix, resets the site, adds/replaces a draft step, writes
a dataset or invokes automatic recovery. The original public request remains in
the trace while an opaque host-local capsule carries exact execution arguments.

The ordered list guard hashes canonical definitions, actual inputs, semantic
subjects, reference time and captured world/authority. Aliases and model call ids
cannot create fresh authority. A failed guard record terminates the loop before
another provider decision, tool or completion. Every member also retains the
ordinary per-call guards.

Private execution distinguishes a held main, an unproven main and a fresh
receipt-backed main. The public envelope contains only status and closed counts:
requested, executed, skipped and an optional unproven count, with closed stopping
reason/index. Unknown mains are neither proved executed nor definitely skipped.
They retain conservative attempted-call quota and stop later members. Known held
mains consume no executed-node allowance. A fresh failure or uncertain reply still
proves an actual command, preserves its receipt and stops the list. The envelope
itself adds no node call, and one outer provider decision is billed once.

Accepted receipts and original errors remain private through later vetoes,
scope loss or exceptions. Outward failures use closed redacted descriptions.
A first report after scope loss is rejected as unproven; an already accepted
report survives later loss. Consumption is not a dispatch/receipt witness.

The assessment transport and provenance factory are private Core features,
shared across bundled copies through scoped process-local state. They are not
model tools or public executors. No-check paths and older adapters keep ordinary
behavior but cannot silently acquire batch eligibility. Trusted wrapper ownership
and the actual adapter attempt observer establish provenance; there is no claim
of cryptographic gate-to-dispatch correlation or global receipt authentication.
